01

진단 일곱

번호는 우선순위가 아니라 참조용이다. 넷은 값을 고르는 일이고 레이아웃을 건드리지 않는다 — 오늘 고칠 수 있다.

  • 1영상 목록이 글자 링크뿐이다구조 유튜브인데 썸네일이 없다. 제목을 다 읽어야 판별된다 — 훑기가 성립하지 않는다. Feed.tsx · VideoRow
  • 2링크 색이 흰 배경에서 대비 미달값 #4a90e2 → 3.29:1. AA는 4.5:1이 필요하다. ui.tsx · link
  • 3「본 영상 ✓」 터치 영역이 약 20px값 권장 44px의 절반 미만. 폰에서 옆 링크가 먼저 잡힌다. VideoRow
  • 4삭제 버튼이 피드에 있다값 훑는 화면에 되돌릴 수 없는 행동. 지운 결과는 다음 「☁️ 올리기」에 드라이브까지 전파된다.
  • 5날짜가 원문 그대로값 2026-08-19를 보고 「며칠 전」을 매번 환산하게 된다.
  • 6로딩이 「불러오는 중…」 글자다구조 채널 40개면 40줄이 깜빡이고, 결과가 오면 높이가 달라져 화면이 튄다.
  • 7본 영상 표시가 흐림 하나뿐값 opacity-45는 다크에서 거의 안 보이고 대비가 깨진다.
02

대비를 실제로 쟀다

#2가 추정이 아닌 이유. 영상 제목은 1.05rem(≈16.8px) semibold라 「큰 글자」 예외(18.66px 굵게)에 못 미친다 — 3:1이 아니라 4.5:1을 맞춰야 한다.

리액트 19가 바꾼 것 #2f6fd0 글자 / 흰 배경 — 제안 4.88통과
리액트 19가 바꾼 것 #7fb3f2 글자 / 어두운 배경 — 제안 8.15통과

문제는 색이 나쁜 게 아니라 색 하나가 두 가지 일을 겸한다는 것이다. 바탕으로 쓸 때(버튼·배지·탭 밑줄)는 #4a90e2로 충분하다 — 대비 기준이 다르다. 글자로 쓸 때만 미달이다. 역할이 둘이면 토큰도 둘이다.

⭐ 이렇게 하면 강조색 값 자체는 안 바뀐다. 40-screens 7절이 경고해둔 CSS 밖 네 군데 — favicon data URI · theme-color · manifest.json · icons/*.svg — 를 한 곳도 안 건드린다.

03

토큰 — 일곱은 그대로, 일곱을 더한다

「역할 이름」 규칙(--blue가 아니라 --accent)은 새 토큰에도 그대로. 스와치가 둘로 갈린 것은 라이트/다크 값이다.

토큰라이트다크쓰는 곳
--color-accent#4a90e2동일바탕 · 테두리 · 탭 막대
--color-link 신규#2f6fd0#7fb3f2글자로 쓰는 파랑 · NEW 바탕
--color-on-link 신규#fff#0b0d11link 바탕 위 글자
--color-surface 신규#ffffff#14171d본 바탕
--color-surface-sunken 신규#f2f4f7#0e1014스켈레톤 · 입력칸 · 썸네일 자리
--color-surface-raised 신규#ffffff#1b1f27모달 · 바텀시트
--color-ink 신규#16181d#e7eaf0본문 · 영상 제목
--color-ink-muted 신규#667085#949cab메타 · 힌트 (--color-muted 후계)
--color-line#8886동일입력칸 · 고스트 테두리
--color-line-faint#8883동일상자 테두리
--color-danger#c0392b동일삭제

⭐ light-dark()는 이미 열려 있던 문이다. 2026-08-05에 color-scheme: light dark를 켜뒀는데, light-dark()는 바로 그 값을 읽어서 갈린다 — 미디어 쿼리를 새로 쓰지 않고 값 자리에서 끝난다. 넓게 받으려면 --color-link 하나만 덮으면 되고, 토큰이 하나라 덮을 곳도 하나다.

⚠︎ --color-muted(#8a8a8a)를 지우지 말고 --color-ink-muted를 옆에 둔 뒤 옮긴다. text-muted는 화면 다섯에 흩어져 있다 — 한 번에 갈아치우면 무엇이 바뀌었는지 못 센다.

크기 — 일곱 종을 다섯으로

셋(.9 / .85 / .8)은 서로 다르려고 다른 게 아니라 그때그때 골라서 달랐다.

--text-sm0.8125 / 4003시간 전 · 37개 중 12개 켜짐
--text-xs0.6875 / 700NEW · 정리 · 삭제

간격 — 4px 배수만

지금의 7 · 18 · 22 · 26 · 2px가 여기로 접힌다.

⚠︎ p { margin: 7px 0 }은 Tailwind preflight를 되돌리려고 넣은 값이다. 브라우저 기본은 1em(≈16px)인데 7px로 적어둔 거라, 8로 옮기면 원래 되돌리려던 값과 더 멀어진다. 여기는 옮기기 전에 「무엇으로 되돌리는 중이었나」를 먼저 정할 것.

05

화면 다섯

폰 폭 기준. 옆으로 밀어서 본다. 구조가 바뀌는 것은 ②피드와 ①채널뿐이고, 나머지 셋은 토큰만 갈아끼운 모습이다.

「더보기」의 미결에 답 하나

40-screens 5절이 「앞에서 3개 / 안 본 것 3개 — 아직 안 정했다」로 남겨둔 자리다. 썸네일이 붙으면 한 줄 높이가 커지므로 이 결정이 더 급해진다.

안 07-30의 문제 재발시간순
앞에서 3개 재발한다 유지
안 본 것만 3개 (정렬 변경) 안 난다 깨진다
안 본 것 3개까지 · 순서 유지 제안 안 난다 유지

최대가 6이라 접힌 높이가 유계다. 6개는 이미 받아와 있으므로 「더보기」는 네트워크 0회 — 40-screens가 LIMIT을 건드리지 말라고 못박은 이유가 여기서 값을 한다.

06

썸네일 — 요청도 쿼터도 늘지 않는다

videoId는 이미 갖고 있다 — video.ts의 videoKey(v)가 그 값이다(본 영상 기록의 열쇠). Worker도, /rss 계약도, 유튜브 Data API 쿼터도 건드리지 않는다.

https://i.ytimg.com/vi/<videoId>/mqdefault.jpg
320×180 · 항상 존재한다

그래도 공짜는 아니다. 늘어나는 것과 대비책:

늘어나는 것대비
이미지 요청 = 채널 수 × 6 (40채널이면 240개) loading="lazy" + decoding="async" — 화면 밖은 안 받는다
이미지가 늦게 오면 화면이 튄다 width/height를 속성으로 박고 자리를 surface-sunken으로 채운다
페이지를 열기만 해도 유튜브 CDN에 요청이 나간다 (지금은 링크를 눌러야 나갔다) referrerpolicy="no-referrer" — 어느 페이지에서 왔는지는 안 보낸다
쇼츠는 세로인데 썸네일은 16:9 레터박스로 온다 object-fit: cover — 위아래 검은 띠가 잘린다
maxresdefault.jpg는 없을 수 있다 쓰지 않는다. mqdefault만 쓴다

⚠︎ channelCache에 썸네일 URL을 저장하지 않는다. videoId에서 매번 조립한다 — 저장하면 URL 규칙이 바뀔 때 낡은 값이 굳고 드라이브 payload도 커진다. 「구독 목록은 저장하지 않는다」와 같은 판단이다.

07

순서

각 단계는 앞 단계 없이도 성립한다. 중간에 멈춰도 화면이 반쯤 바뀐 상태로 남지 않는다.

A

값만 고른다 — 토큰도 레이아웃도 안 건드린다

다섯 다 되돌리기가 공짜다. 여기서 멈춰도 앱은 더 나아진 채로 끝난다.

  • --color-link·--color-on-link 추가 → 링크·NEW 배지에 적용 · #2 · 토큰 2줄 + 치환
  • ✓/○ 터치 영역 44px — 투명 여백으로 넓힌다(보이는 크기는 그대로) · #3
  • 본 영상 표시를 색 + 기호로 · #7
  • 피드에서 삭제 버튼 제거 — 채널 화면에 이미 있다 · #4
  • relativeTime() — video.ts의 isNew 옆에 · #5
B

썸네일 — 가장 크게 값하는 한 걸음

VideoRow 구조 교체 + 스켈레톤. A의 「본 영상 표시」가 여기서 완성된다.

  • 🚦 먼저 폰에서 40채널을 한 번 열어 이미지 240개의 체감을 잰다. 느리면 「안 본 것 3개까지」를 B와 함께 넣는다 — 접힌 상태에서 이미지가 절반이 된다.
C

토큰 확장 — 표면·글자·크기·간격·반경

화면 다섯을 한 번에 훑는 작업이라 A·B보다 지루하고 위험하다.

  • ⚠︎ 색 정리(2026-08-05) 때 쓴 방법을 그대로: 보이는 변화가 없어야 하는 부분은 측정해서 확인한다.
  • --color-muted → --color-ink-muted는 값이 바뀌므로(#8a8a8a → #667085) 예외 — 의도한 변화이니 따로 표시하고 옮긴다.
D

#/styleguide 화면

C가 끝난 다음이다. 정리되지 않은 컴포넌트를 진열해봐야 볼 게 없다.

  • 40-screens는 styleguide.html 한 장으로 정해뒀지만 그건 바닐라 시절 계획이다. 화면 하나로 두면 진짜 컴포넌트를 그대로 쓴다 → 어긋날 수가 없고, 별도 CSS 걱정도 사라진다.
  • ⚠︎ 탭에는 안 넣는다. 주소로만 연다.
⏸

대기 — 신호등이 켜지면

  • 하단 고정 탭바 — 피드 스크롤이 길어져 탭 되돌아가기가 귀찮아질 때 (썸네일이 붙으면 그날이 앞당겨진다)
  • 주제 칩 필터 · 채널 접기 — 켠 채널이 20개를 넘어 「무엇을 볼지」가 한 화면에 안 잡힐 때
  • 통합 타임라인 — 채널별 묶음보다 시간순이 더 보고 싶어질 때
  • 다크에서 --color-accent 자체를 밝히기 — 지금 대비는 통과하므로 급하지 않다. 건드리면 CSS 밖 네 군데가 딸려온다
