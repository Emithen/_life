> 기준: youtube-feed `293e70b` · 2026-08-21

## 0. 왜 이 문서가 생겼나

색 토큰 7개(2026-08-05)와 Tailwind 이식(2026-08-17)으로 **색은 정리됐다.**
그런데 색만 정리됐다. 지금 코드에서 색이 아닌 값은 전부 그 자리에서 정해진다:

```
글자 크기   1.5rem · 1.05rem · .9rem · .85rem · .8rem · .75rem · .68rem   ← 7종
여백        7px · 18px · 22px · 26px · 2px · 2.5 · 3.5                    ← 제각각
반경        rounded-lg · rounded-md · rounded-[5px] · rounded-[10px]      ← 4종
```

화면 다섯에 7종 크기면 **"이건 어느 크기지?"를 매번 다시 정하고 있다는 뜻**이다.
색에서 22군데 하드코딩을 겪고 토큰으로 접었던 것과 **정확히 같은 상황**이고,
그때의 교훈("화면이 늘어난 뒤에 정리했으면 22군데가 80군데가 됐다")도 그대로 적용된다.

그리고 색 쪽에도 **정리 때 안 보였던 결함이 둘** 남아 있다 — 3절.

## 1. 진단 — 지금 화면의 문제 일곱

번호는 우선순위가 아니라 **참조용**이다. 순서는 8절에 따로 있다.

| # | 문제 | 어디 | 성격 |
|---|---|---|---|

## 2. 방향 — "조용한 껍데기, 시끄러운 내용물"

한 문장: **색은 썸네일이 낸다. 앱은 회색으로 물러난다.**

- 지금은 반대다. 썸네일이 없어서 **강조색이 화면의 모든 제목을 칠하고 있다.**
  40개 채널 × 6개 영상 = 파란 줄 240개. 강조색이 240번 쓰이면 그건 강조가 아니라 본문색이다
- 썸네일이 붙으면 색은 저절로 내용물로 옮겨간다 → **강조색은 「지금 상호작용할 수 있는 것」에만** 남긴다:
  활성 탭 · NEW 배지 · 주된 버튼 · 포커스 링. 영상 제목은 **본문색(ink)** 으로 내린다
- ⭐ **이게 1번(썸네일)이 단순한 기능 추가가 아닌 이유다.** 썸네일은 색의 예산을 되찾아준다

### 안 바꾸는 것 (일부러)

| | 왜 |
|---|---|
| 강조색 `#4a90e2` **자체** | CSS 밖 네 군데(favicon data URI · `theme-color` · `manifest.json` · `icons/*.svg`)에 박혀 있다. 7절이 경고해둔 그 지점이다. **값을 안 바꾸면 그 넷을 안 건드린다** |
| 「역할 이름」 규칙 | `--blue`가 아니라 `--accent`. 새 토큰도 전부 이 규칙을 따른다 |
| 회색 `#888+알파` | 라이트/다크 양쪽에서 묻히는 값. 선(line) 계열은 그대로 둔다 |
| 탭의 이모지 | 이 앱의 말투다. 크기와 정렬만 정리한다 |
| 640px 단일 컬럼 | 폰이 주 사용처다. 데스크톱 전용 레이아웃을 만들 이유가 없다 |

## 3. 색 — 토큰 둘을 **더한다**. 기존 일곱은 그대로 둔다

### 3-a. 새 토큰: `--color-link` (⭐ 이 문서의 핵심 한 줄)

문제(#2)는 "강조색이 나쁘다"가 아니라 **강조색 하나가 두 가지 일을 겸한다**는 것이다:

```
바탕으로 쓸 때 (버튼·배지·활성 탭 밑줄)   → #4a90e2 로 충분하다. 대비 기준이 다르다
글자로 쓸 때  (영상 제목·링크)            → 흰 배경에서 3.29:1. 미달이다
```

역할이 둘이면 **토큰도 둘**이다. 7절이 정한 「역할 이름」 규칙이 그대로 답을 준다.

```css
@theme {
  --color-accent: #4a90e2;        /* 그대로. 바탕·테두리·아이콘에 쓴다 */
  --color-link: light-dark(#2f6fd0, #7fb3f2);   /* 새로 만든다. 글자에 쓰는 파랑 */
  --color-on-link: light-dark(#fff, #0b0d11);   /* --color-link 바탕 위에 얹는 글자 */
}
```

- ⭐ **`light-dark()`는 이 프로젝트에 이미 열려 있던 문**이다. `:root { color-scheme: light dark }`를
  2026-08-05에 켜뒀는데(`index.css`), `light-dark()`는 **바로 그 값을 읽어서 갈린다.**
  미디어 쿼리를 새로 쓰지 않고 값 자리에서 끝난다
- ⚠️ 지원: 크롬 123·사파리 17.5·파이어폭스 120(2024). 폰 브라우저는 문제없지만
  더 넓게 받으려면 `@media (prefers-color-scheme: dark)`로 `--color-link`만 덮으면 된다.
  **토큰이 하나라서 덮을 곳도 하나다**
- ⚠️ NEW 배지도 `--color-link` 바탕 + `--color-on-link` 글자로 바꾼다.
  지금 `bg-accent text-accent-ink`는 `.68rem` 굵은 글자에 3.29:1이라 가장 나쁜 조합이다

### 3-b. 새 토큰: 표면·글자 계층

지금 배경과 글자색은 **브라우저가 준다**(`Canvas`/`CanvasText` + `color-scheme`).
그건 좋은 결정이었지만 — 값을 안 정하니 다크 오버라이드가 필요 없었다 —
**두 번째 표면이 필요해지는 순간 무너진다**: 스켈레톤·모달·접힌 상자·입력칸 바탕.

`Canvas` 하나뿐이라 지금은 그 자리를 전부 **테두리**로 때우고 있다
(`border-line-faint`가 붙은 상자 셋). 그래서 화면이 선으로만 나뉜다.

```css
--color-surface:        light-dark(#ffffff, #14171d);  /* 본 바탕 */
--color-surface-sunken: light-dark(#f2f4f7, #0e1014);  /* 스켈레톤·입력칸·썸네일 자리 */
--color-surface-raised: light-dark(#ffffff, #1b1f27);  /* 모달·바텀시트 */
--color-ink:            light-dark(#16181d, #e7eaf0);  /* 본문 */
--color-ink-muted:      light-dark(#667085, #949cab);  /* 메타·힌트 (기존 --color-muted 대체) */
```

- ⚠️ **`--color-muted`(#8a8a8a)를 지우지 말고 `--color-ink-muted`를 옆에 둔 뒤 옮긴다.**
  `text-muted`는 화면 다섯에 흩어져 있다. 한 번에 갈아치우면 무엇이 바뀌었는지 못 센다
  (색 정리 때 "요소 24개의 계산된 색을 전후 비교"한 그 방식이 여기서도 필요하다)
- ⚠️ `Canvas`/`CanvasText`는 `<dialog>` 때문에 넣은 것이다. **`--color-surface-raised`가
  그 자리를 대신하면 둘을 지울 수 있다** — 다만 그건 3-b가 끝난 다음의 정리다

## 4. 크기 — 7종을 5종으로

| 토큰 | 값 | 굵기 | 줄간 | 지금 이 자리에 있던 값 |
|---|---|---|---|---|
| `--text-title` | `1.375rem` | 700 | 1.3 | `h1` `1.5rem` |
| `--text-lg` | `1.0625rem` | 600 | 1.45 | 링크·영상 제목 `1.05rem`, 채널 제목 `1.05rem` |
| `--text-base` | `0.9375rem` | 400 | 1.6 | 본문(지정 없음 = 1rem) |
| `--text-sm` | `0.8125rem` | 400 | 1.5 | `.9rem`(상태·탭) · `.85rem`(✓버튼) · `.8rem`(힌트) |
| `--text-xs` | `0.6875rem` | 700 | 1 | `.75rem`(삭제) · `.68rem`(NEW) |

- ⭐ **줄어드는 게 아니라 합쳐지는 것이다.** `.9`/`.85`/`.8`은 서로 다르려고 다른 게 아니라
  **그때그때 골라서** 달랐다. 셋을 `--text-sm` 하나로 합치면 화면이 조용해진다
- ⚠️ `h1`을 `1.5` → `1.375`로 줄이는 건 유일하게 **눈에 보이는 변화**다. 탭과 함께 상단에
  고정되는 걸 전제로 한 값이라, 고정을 안 할 거면 `1.5`로 둬도 된다

### 간격 — 4px 배수만 쓴다

`4 · 8 · 12 · 16 · 24 · 32`. 지금의 `7px`→`8`, `18px`→`16`, `22px`·`26px`→`24`, `2px`→`4`.

> ⚠️ **`p { margin: 7px 0 }`은 Tailwind preflight를 되돌리려고 넣은 값**이다(index.css 주석).
> 브라우저 기본이 `1em`(≈16px)인데 7px로 적어둔 거라, `8`로 옮기면 **원래 되돌리려던
> 기본값과 더 멀어진다.** 여기는 값을 옮기기 전에 "무엇으로 되돌리는 중이었나"를 먼저 정할 것.

### 반경

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--radius-sm` | `6px` | 배지·작은 버튼 |
| `--radius-md` | `10px` | 버튼·입력칸·상자 (지금 `rounded-lg`/`[10px]`가 이미 8~10) |
| `--radius-lg` | `14px` | 카드·모달·바텀시트 |
| `--radius-full` | `999px` | 주제 칩 |

### 터치 영역 (#3)

**최소 44×44px.** 지금 「✓/○」는 `px-1` + `.85rem`이라 실측 약 20px이다.
글자를 키우지 말고 **투명한 여백으로 넓힌다**(`p-2.5 -m-2.5` 꼴) — 보이는 크기는 그대로,
누르는 크기만 커진다.

### 5-a. VideoRow — 구조

```
┌──────────┐  ⌐NEW¬ 리액트 19가 바꾼 것 세 가지          ← --text-lg / --color-ink / 2줄 말줄임
│ 썸네일    │  3시간 전                            ✓/○   ← --text-sm / --color-ink-muted
│ 112×63   │                                             ← 터치 44px
└──────────┘
```

- 썸네일 **112×63**(16:9), `--radius-md`. 640px 컨테이너·폰 양쪽에서 4~5줄이 한 화면에 들어온다
- 제목은 **2줄에서 자른다**(`line-clamp-2`). 자르지 않으면 카드 높이가 제각각이라 훑기가 안 된다
- ⭐ **NEW 배지의 자리가 바뀐다.** 40-screens는 "줄 맨 앞에 둬야 눈에 띈다"고 적어뒀는데,
  썸네일이 붙으면 **줄 맨 앞은 썸네일**이다. 배지는 썸네일 좌상단으로 옮긴다 —
  근거("훑을 때 왼쪽 끝에서 잡힌다")는 그대로 지켜지고 위치만 따라간다
- 본 영상(#7): `opacity-45` 대신 **① 썸네일만 `opacity: .5` ② 제목은 `--color-ink-muted`
  ③ ✓ 기호.** 흐림은 **정보가 없는 쪽(이미지)에만** 걸고 글자는 대비를 지킨다

### 5-b. 썸네일을 어디서 가져오나 — ⭐ 요청도 쿼터도 늘지 않는다

```
https://i.ytimg.com/vi/<videoId>/mqdefault.jpg     320×180, 항상 존재
```

`videoId`는 **이미 갖고 있다** — `video.ts`의 `videoKey(v)`가 그 값이다(본 영상 기록의 열쇠).
그래서 **Worker도, `/rss` 계약도, 유튜브 Data API 쿼터도 건드리지 않는다.**
40-screens 6절의 쿼터 함정과 무관한 길이다.

⚠️ 그래도 공짜는 아니다. 늘어나는 것과 대비책:

| 늘어나는 것 | 대비 |
|---|---|
| 이미지 요청 = 채널 수 × 6 (40채널이면 240개) | `loading="lazy"` + `decoding="async"`. 화면 밖은 안 받는다 |
| 이미지가 늦게 오면 화면이 튄다 | `width`/`height`를 **속성으로** 박고 자리를 `--color-surface-sunken`으로 미리 채운다 |
| **페이지를 열기만 해도 유튜브 CDN에 요청이 나간다** (지금은 링크를 눌러야 나갔다) | `referrerpolicy="no-referrer"` — 어느 페이지에서 왔는지는 안 보낸다 |
| 쇼츠는 세로인데 썸네일은 16:9 레터박스로 온다 | `object-fit: cover`. 위아래 검은 띠가 잘린다 |
| `maxresdefault.jpg`는 **없을 수 있다** | 쓰지 않는다. `mqdefault`만 쓴다 |

- ⚠️ **캐시(`channelCache`)에 썸네일 URL을 저장하지 않는다.** `videoId`에서 매번 조립한다 —
  저장하면 URL 규칙이 바뀔 때 낡은 값이 굳고, 드라이브 payload도 커진다
  (「구독 목록은 저장하지 않는다」와 같은 판단)

### 5-c. 상대 시간 (#5)

`video.ts`에 `isNew` 옆으로 `relativeTime(v)`를 둔다 — 같은 파일에 있어야 할 이유가 같다
("영상 한 편을 읽는 규칙. 화면 여러 곳이 같이 쓴다").

```
< 1시간   방금
< 24시간  N시간 전      ← NEW 배지가 붙는 구간과 정확히 겹친다
< 7일     N일 전
그 외     M월 D일        ← 올해면 연도 생략, 아니면 YY.MM.DD
```

⚠️ `published`(ISO8601·시각까지)가 있어야 「N시간 전」이 정확하다. 없으면(옛 Worker가 만든
캐시) `date`(날짜만)뿐이라 「N일 전」부터만 쓴다 — `isNew`가 이미 쓰는 폴백과 같은 구조다.

## 8. 순서 — 무엇부터 하나

각 단계는 **앞 단계 없이도 성립**한다. 중간에 멈춰도 화면이 반쯤 바뀐 상태로 남지 않는다.

### A. 값만 고른다 — ✅ 구현됨 (2026-08-22, `fc85f32` · 브랜치 `design/a-step`)

> ⭐ **막상 붙여보니 초안이 세 군데 틀렸다.** 값을 고르는 일이라 해도 **재보기 전에는 모른다** —
> 셋 다 브라우저에서 실제로 렌더해 계산된 색과 히트영역을 재서 나왔다.
>
> **① 대비 미달이 NEW 배지만이 아니었다.** 초안은 배지(`.68rem`)만 짚었는데,
> **주 버튼 `btn`과 의견 화면의 선택 칩도 같은 3.29:1** 이었다. 둘 다 `1rem semibold`라
> 「큰 글자」 예외(18.66px 굵게)에 **못 미친다** — 예외 경계를 배지에만 적용한 게 실수다.
>
> **② 흐림을 `--muted`로 바꾸는 것은 고친 게 아니었다.** `#8a8a8a`는 흰 배경에서
> **3.45:1**이라 그 자체가 미달이다. `opacity-45`(미달)를 `--muted`(미달)로 바꾸면
> **미달을 미달로 옮기는 것뿐**이다. → `--color-ink-muted`(4.97 / 6.78)를 **C단계에서 당겨왔다.**
> ⭐ 규칙으로 남길 것: **「흐리게」를 「색을 낮추기」로 바꾸려면 낮춘 색도 읽혀야 한다.**
>
> **③ 히트영역은 패딩만으로 안 커졌다.** `px-3 py-3`을 줘도 실측 **32×38**이었다.
> 크기를 명시(`w-11 h-11`)해야 44가 나온다. 그리고 44로 키우니 **`✓`가 혼자 다음 줄로
> 떨어졌다** — 날짜와 토글을 `whitespace-nowrap`으로 묶어야 성립한다.
> ⚠️ **접근성 수정이 레이아웃을 건드린다.** "값만 고른다"가 완전히 참은 아니었다.

**실측 (브라우저가 칠한 배경 기준 · 라이트 / 다크)**

| 자리 | 전 | 후 |
|---|---|---|

| ✓/○ 히트영역 | 20px 안팎 | **44×44** |

⭐ **`--color-accent` 값은 한 글자도 안 바꿨다** → CSS 밖 네 군데를 안 건드렸다(계획대로).
⭐ `light-dark()`가 `color-scheme: light dark`(2026-08-05)를 읽어 **미디어 쿼리 없이** 갈렸다.
⚠️ 빌드 시 Lightning CSS가 `light-dark()`를 자기 폴리필(`--lightningcss-light/dark`)로
바꾼다 — `@media (prefers-color-scheme:dark)`로 제대로 감싸는 것을 확인했다.
