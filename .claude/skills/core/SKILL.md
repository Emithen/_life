# core — 프로젝트 코어 로직 설명

**목적**: 같은 질문을 반복해도 (1) 항상 같은 답을 주고 (2) 코드를 매번 다시 훑지 않아 토큰을 아낀다.
그래서 답은 **미리 정리해둔 `docs/core/` 문서에서 가져온다. 코드 탐색으로 재구성하지 않는다.**

## 절차

### 1. 어떤 프로젝트인지 정한다

- 사용자가 인자로 줬으면(`/core youtube-feed`) 그대로 쓴다.
- 대화 맥락상 명백하면 그걸 쓰되, **한 줄로 밝히고** 진행한다.
- 불명확하면 `docs/core/projects.md`를 읽고 **선택지를 제시해 고르게 한다.** 멋대로 고르지 않는다.

### 2. 개요를 읽는다 (항상)

`docs/core/<프로젝트>/00-overview.md` — 이것만으로 대부분의 질문이 해결된다.

### 3. 필요할 때만 세부 문서를 추가로 읽는다 ⚠️ 토큰 절약의 핵심

질문이 특정 주제를 겨냥할 때만 **해당 파일 1개**를 더 읽는다. 전부 읽지 않는다.

| 질문이 이런 쪽이면 | 읽을 파일 (youtube-feed) |
|---|---|
| 데이터 흐름, 배치 vs 실시간, 계약(JSON 모양) | `10-flow-and-contracts.md` |
| RSS가 뭔지, channel_id 찾는 과정, @핸들 | `20-rss-and-channel-id.md` |
| CORS, 프록시, Cloudflare Worker, 캐싱 | `30-cors-and-relay.md` |
| 화면 구조, 라우팅, UI/디자인 시스템, 구독≠피드 | `40-screens-and-ui.md` (설계 문서 — 아직 구현 전) |
| 예전에 터졌던 문제, 함정, 왜 이렇게 짰나 | `90-gotchas.md` |

`category-theory`는 개요 문서가 **지도 역할만** 하고 진짜 내용은 저장소 안에 있다:

| 질문이 이런 쪽이면 | 읽을 파일 (category-theory) |
|---|---|
| 진도, 다음에 뭘 배우나, 단계 구성 | `category-theory/ROADMAP.md` |
| 특정 개념(함자·모나드·요네다 …)을 뭐라고 정리했나 | `category-theory/notes/<번호>-<개념>.md` **1개만** |
| 법칙을 코드로 어떻게 확인했나 | `category-theory/src/<번호>-*.ts` |

`claude-code-mastery`도 같은 꼴이다 — 개요는 `docs/core/`, 진도는 `claude-code-mastery/ROADMAP.md`.

"전반적으로 설명해줘" 같은 광범위 요청이면 **개요만 읽고 답한 뒤**, 더 깊이 볼 주제를 제안한다.

### 4. 문서가 낡았는지 확인한다 (명령 1회, 거의 공짜)

각 문서 헤더에 `기준: <저장소> <커밋>` 이 적혀 있다. 현재와 비교한다:

헤더의 `<저장소>`가 어느 git 저장소인지 보고 그쪽을 조회한다.
`youtube-feed`는 **중첩된 별도 저장소**이고, 나머지(`_life`)는 이 저장소 자신이다.

```bash
# 헤더가 "기준: youtube-feed <커밋>" 인 경우
git -C /Users/soggyfries/Desktop/_life/youtube-feed log --oneline <기준커밋>..HEAD | head -20

# 헤더가 "기준: _life <커밋>" 인 경우 (claude-code-mastery, category-theory)
git -C /Users/soggyfries/Desktop/_life log --oneline <기준커밋>..HEAD | head -20
```

- 차이가 없으면 아무 말도 하지 않는다.
- 커밋이 쌓였으면 답변 **끝에** 한 줄로: "문서 기준 이후 N개 커밋 있음 — 갱신할까요?"
- 문서 내용과 **명백히 모순되는** 변경을 발견하면, 그 부분은 코드를 확인해 바로잡고 답한다.

## 답변 규칙

- 문서를 그대로 낭독하지 말고 **질문에 맞춰 필요한 부분만** 재구성한다.
- 코드 위치를 언급할 땐 클릭 가능한 링크로: `[collect.py](youtube-feed/collect.py)`
- 문서에 없는 내용을 물으면: 문서 범위 밖임을 밝히고 → 코드를 확인해 답한 뒤 → **문서에 추가할지 제안**한다.
  (이렇게 캐시를 키운다. 다음부턴 그 질문도 싸진다.)
- 설명 뒤에 "더 깊이 볼 주제"를 1~2개 제안해 다음 행동을 쉽게 만든다.
