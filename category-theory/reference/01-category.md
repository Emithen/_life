**한 줄**: 대상들과 그 사이의 사상들, 그리고 **결합법칙·항등법칙을 지키는 합성**이
갖춰진 구조.

정확히 이것뿐이다. 네 개의 데이터 + 두 개의 법칙:

| | 이름 | 내용 |
|---|---|---|
| 데이터 | 대상 | `A`, `B`, `C`, … (안은 안 본다) |
| 데이터 | 사상 | 각 쌍 `(A,B)`마다 화살표들의 모음 `Hom(A,B)` |
| 데이터 | 합성 | `Hom(B,C) × Hom(A,B) → Hom(A,C)` — **항상 정의돼야 한다** |
| 데이터 | 항등 | 각 대상 `A`마다 `id_A : A → A` |
| 법칙 | 결합 | `h ∘ (g ∘ f) = (h ∘ g) ∘ f` |
| 법칙 | 항등 | `id_B ∘ f = f = f ∘ id_A` (단, `f : A → B`) |

**왜 이 이름인가**
→ [00-why.md](00-why.md) 참고. 요약하면 **"분류"와는 무관한 역사적 오명**이다.
`Hom`은 homomorphism(준동형사상)의 줄임 — 원래 대수 구조 사이의 사상을 세던 데서 왔다.
지금은 "사상 전부"를 뜻하는 일반 용어로 굳었다.

**TS에서는**

```ts
export const id = <A>(a: A): A => a;
export const compose = <A, B, C>(g: (b: B) => C, f: (a: A) => B) =>
  (a: A): C => g(f(a));
```

- 대상 = 타입, 사상 = 함수, 합성 = 함수 합성, 항등 = `id`.
- 두 법칙은 **여기서 증명 없이 성립한다** — 함수 합성이 원래 그런 것이라서.
  그래서 1단계 코드는 "법칙이 성립함을 확인"이지 "법칙을 강제"가 아니다.

**흔히 막히는 지점 ① — 범주는 그래프가 아니다**

"점과 화살표 그림"이라는 설명만 들으면 **그래프랑 뭐가 다르냐**에서 막힌다.
차이는 두 개다:

1. **합성이 항상 있어야 한다.** `A→B`, `B→C`가 있으면 `A→C`가 **반드시 존재해야** 한다.
   그래프는 그런 의무가 없다.
2. **그 합성이 결합법칙을 지켜야 한다.**

즉 그래프는 데이터고, 범주는 **데이터 + 법칙**이다.
(뒤집으면: 아무 그래프나 주고 "합성을 다 만들어 넣어라"라고 하면 범주가 된다 — 자유범주.)

**흔히 막히는 지점 ② — 사상이 함수가 아닐 수도 있다**

가장 크게 넘어지는 지점. "사상 = 함수"로 읽기 쉽다. 반례 두 개:

- **포셋(순서집합)**: 대상 = 원소, 사상 = `a ≤ b` 라는 **사실 하나**. 함수가 아니다.
  합성 = 추이성(`a≤b`, `b≤c` ⟹ `a≤c`), 항등 = 반사성(`a≤a`). 두 법칙 자동 성립.
  → `Hom(a,b)`는 원소가 **0개 아니면 1개**다. "화살표가 여러 개"라는 그림조차 필요 없다.
- **모노이드**: 대상이 **딱 하나**. 사상 = 모노이드의 원소들. 합성 = 모노이드 연산.
  예) 대상 `*` 하나, 사상 = 모든 문자열, 합성 = 이어붙이기, `id` = `""`.

이 둘을 보면 "대상의 내부를 안 본다"는 말이 왜 필요한지가 드러난다.
내부를 안 보기 때문에 **집합이든 순서든 문자열이든 같은 말이 통한다.**

**흔히 막히는 지점 ③ — `id`는 "아무것도 안 함"이 아니라 "합성의 단위원"이다**

`id`는 "쓸데없는 함수"로 보이지만, 역할은 모노이드의 `1`과 같다.
`id`가 없으면 **동형(isomorphism)을 정의할 수 없다** — `g∘f = id`, `f∘g = id` 로
"서로를 되돌린다"를 말해야 하는데 기준이 사라진다.
범주론이 "무엇이 같은가"를 다루는 이론이니, `id`는 사실 제일 중요한 데이터다.
