## 🧠 관통 개념 — "범주론은 합성(composition)의 학문이다"

```
        f            g
   A ──────▶ B ──────▶ C
   │                   ▲
   └───────────────────┘
            g ∘ f          ← 이게 존재한다는 것이 전부의 출발점
```

범주는 딱 세 개를 요구한다:

1. **대상(object)** — 점. 안이 뭔지 묻지 않는다.
2. **사상(morphism)** — 대상 사이의 화살표.
3. **합성(∘)** — 화살표 두 개를 이어 붙이면 **화살표 하나가 나온다.**

그리고 두 개의 법칙만 지키면 된다:

| 법칙 | 식 | 뜻 |
|---|---|---|
| 결합법칙 | `h ∘ (g ∘ f) = (h ∘ g) ∘ f` | 어디서 끊어 묶든 같다 → 괄호를 안 써도 된다 |
| 항등법칙 | `id ∘ f = f = f ∘ id` | 아무것도 안 하는 화살표가 각 대상마다 있다 |

**왜 프로그래머에게 이게 중요한가**: 우리가 복잡도를 이기는 유일한 방법이 "쪼개고 다시
붙이기"인데, 범주론은 **붙이기가 성립하기 위한 최소 조건**을 정확히 말해준다.
앞으로 배울 모든 것(함자·자연변환·수반·모나드)은 **"무엇을 합성 가능하게 만드는가"**의
서로 다른 답일 뿐이다.

| 배울 것 | 무엇을 합성하나 |
|---|---|
| Category | 함수 |
| Functor | 범주 (구조를 보존하며 통째로 옮김) |
| 자연변환 | 함자 |
| Monad | 함수인데 결과가 상자에 든 것 (Kleisli 화살표) |
| 수반 | 반대 방향 함자 두 개를 짝지음 |

### 3개의 반직관적 사실 (여기서 대부분 넘어진다)

1. **대상의 내부는 볼 수 없다.**
   범주론에서 "집합 A의 원소"는 반칙이다. 오직 화살표만으로 말해야 한다.
   → 원소가 필요하면 `1 → A` 라는 **화살표**로 표현한다. 이 전환이 처음의 벽이다.
2. **정의는 "무엇이냐"가 아니라 "무엇과 어떻게 연결되냐"로 한다 (보편성질).**
   곱(product)은 "튜플"이 아니다. "두 사영을 갖고, 그런 것들 중 가장 일반적인 것"이다.
   → 그래서 구현이 뭐든 **유일한 동형(isomorphism)까지 같다.**
3. **화살표를 전부 뒤집으면 정리가 공짜로 하나 더 생긴다 (쌍대성).**
   곱을 뒤집으면 쌍대곱, 시작대상을 뒤집으면 끝대상. 절반은 안 배워도 된다.

### 자가 점검 (답하면 0단계 통과)

1. 대상이 딱 하나뿐인 범주가 있을 수 있나? 있다면 그건 뭔가?
2. "범주는 화살표 그림이다"가 왜 부정확한 설명인가?
3. TypeScript의 타입과 함수는 진짜 범주를 이루는가? 어디서 어긋나나?

<details><summary>답</summary>

1. 있다. 대상 1개 + 사상들 = **모노이드**. 사상의 합성이 모노이드 연산, `id`가 항등원.
   ("대상이 많아야 범주"라는 인상이 틀렸다는 걸 보여주는 예.)
2. 그림에는 없는 두 요구가 범주엔 있다 — **합성이 항상 정의돼야 하고**, 그 합성이
   **결합법칙을 지켜야** 한다. 화살표만 그린 그래프는 아직 범주가 아니다.
3. 이상화하면 그렇다. 어긋나는 지점: 부작용, 예외, 무한 루프(비종료), `null`/`undefined`,
   그리고 `f`와 `g`가 같은 함수인지 판정할 방법이 없다는 것. → 2단계 주제.
</details>

### 🟠 6단계 — 대수적 데이터 타입
- [ ] 왜 sum / product라 부르나 (타입 산술)
- [ ] `Maybe<A> = 1 + A`, `[A, B] = A × B` 를 세어서 확인
- [ ] TS의 유니온이 진짜 쌍대곱이 아닌 지점 (`A | A = A`)

### 🟠 7단계 — Functor ⚠️ 최대 난관
- [ ] 함자 = 대상 매핑 + 사상 매핑 + 두 법칙 (`map id = id`, `map (g∘f) = map g ∘ map f`)
- [ ] **TS엔 higher-kinded type이 없다** → URI/Kind 인코딩(defunctionalization) 도입
- [ ] ⚠️ 이 지저분함은 **범주론이 아니라 TS의 한계**다 — 노트에 분리해서 적을 것
- [ ] Identity, Const, Maybe, Array, Reader(`(r) => a`) 다섯 개 직접 구현

### 🟠 8단계 — 함자의 종류
- [ ] bifunctor / 반변함자(contravariant) / profunctor
- [ ] `(a: A) => R` 이 A에 대해 반변인 것 ↔ TS의 변성(variance) 규칙 연결

### 🔴 9단계 — 자연변환
- [ ] 함자 사이의 사상, 자연성 사각형(naturality square)
- [ ] **파라메트릭 다형성 = 자연성** — `<A>(as: A[]) => Maybe<A>` 는 공짜로 자연변환
- [ ] 함자 범주 `[C, D]`

### 🔴 10단계 — Hom 함자·표현가능 함자
