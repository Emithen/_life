## 🧠 관통 개념 — "에이전트 = 루프"

```
① 컨텍스트 창(모델이 지금 볼 수 있는 모든 것)
        ↓
② 모델이 읽고 다음 행동을 결정
        ↓
③ 도구(tool)를 호출
        ↓
④ 도구 결과가 컨텍스트에 추가됨
        ↓
   ①로 돌아가 반복 (끝날 때까지)
```

배우는 모든 것(skill·hook·subagent·worktree·MCP·loop)은 이 루프의 **한 부분을
조종하는 서로 다른 방법**일 뿐이다.

| 배울 것 | 루프에서 조종하는 부분 |
|---|---|
| CLAUDE.md · memory · skill · MCP resource | ① 뭐가 컨텍스트에 들어가나 |
| MCP · 권한(permission) | ③ 어떤 도구를 쓸 수 있나 |
| hook | 루프 주변에서 자동으로 일어나는 일 |
| subagent · worktree | 루프가 곁가지로 갈라지는 방식 |
| loop · scheduled task | 루프가 시간에 걸쳐 반복되는 방식 |

### 4개의 반직관적 사실 (고수준 방법론의 근거)

1. **모델은 기억하지 못한다 — 매 턴 전부 다시 읽는다.**
   모델 = 상태 없는 함수(context in → 다음 행동 out). 상태는 전부 하네스(파일·루프·memory)에 있다.
   → "컨텍스트에 없는 건 존재하지 않는다."
2. **컨텍스트 창 = 세계의 전부이자 유한한 자원.**
   꽉 차면 요약되며 정보가 손실되고, 중요한 지시가 잡음에 파묻힌다.
   → agent coding의 핵심 기술 = "컨텍스트에 뭘 넣고 뺄지 관리" = context engineering.
3. **도구가 유일한 손이다.** 모델은 텍스트를 내뱉거나 도구를 호출할 뿐.
   → MCP = 손 붙이기, 권한 = 손 막기. 모든 결과는 다시 컨텍스트 안 텍스트로 돌아온다.
4. **모든 기능은 "루프의 특정 통증"에 대한 처방이다.**

| 통증 | 처방 | 루프에서 |
|---|---|---|
| 같은 맥락을 매번 다시 설명하네 | CLAUDE.md | 매 세션 자동으로 ①에 주입 |
| 이 전문지식은 너무 커서 항상 넣긴 부담 | skill | 필요할 때만 ①에 로드 |
| 이 하위작업 과정이 내 컨텍스트를 더럽혀 | subagent | 별도 루프에서 하고 결론만 회수 |
| 모델이 기억하든 말든 무조건 실행됐으면 | hook | 루프 바깥의 결정론적 코드 |
| 병렬 작업이 한 폴더에서 충돌해 | worktree | 파일시스템까지 격리 |
| 이걸 주기적으로 반복하고 싶어 | loop / scheduled task | 루프를 시간축으로 반복 |

### 자가 점검 (답하면 0단계 통과)

1. 세션 초반 지시를 모델이 뒤에서 안 지키기 시작한다 — 루프 관점에서 왜?
2. CLAUDE.md와 skill의 결정적 차이 하나는?
3. subagent에게 "결론만 줘"가 왜 현명한가?

<details><summary>답</summary>

1. 세션이 길어져 그 지시가 컨텍스트에서 밀려나거나 요약되며 희석됨 → 모델엔 "없는" 지시.
2. CLAUDE.md는 항상 자동 로드, skill은 필요할 때만 로드. "상시 비용을 치를 만큼 보편적이냐"가 갈림.
3. 과정의 파일 덤프가 유한한 메인 컨텍스트를 낭비·희석. 결론만 받으면 신호 대 잡음비 유지.
</details>
